# UI Design, Style & Brevity Rules

## 1. Sleek Minimal UI & Color Rules
* **Monochrome + Single Accent Palette:** Use neutral zinc/slate surfaces (#09090b, #121215, #18181b, border #27272a), crisp off-white text (#fafafa), muted zinc secondary text (#a1a1aa), and a single subtle indigo accent (#6366f1).
* **No Green Text (No Inline Backticks):** Never use green color text in UI, CSS, or documentation. Never wrap words, phrases, URLs, or terms in single inline backticks in Markdown documents or chat responses, because the Markdown viewer renders inline code spans in green text. Use **bold** or *italics* instead.
* **No Rainbow or Neon Colors:** Never use neon orange, bright yellow, or multi-colored status badges.
* **Generous Whitespace:** Use spacious card padding (1.5rem to 2rem), wide grid gaps (1.25rem to 1.75rem), and clean alignment so screens never feel cluttered.
* **Zero Instructional Paragraphs in UI:** Never add explanatory paragraphs, onboarding banners, or repetitive subtitles inside app views.
* **1-2 Word Navigation & Labels:** Keep tab names, badges, and field labels to 1 to 3 words maximum.

## 2. Writing & Formatting Rules
* **Short Headers:** Limit headings to 2 to 5 words.
* **Clear Narrative in Docs:** In strategy and explanation documents, preserve the full persuasive reasoning and narrative flow (*Why -> Analogy -> Architecture -> Examples*) in plain, easy-to-read sentences without filler words.
* **No Horizontal Dividers:** Never use horizontal divider lines in Markdown content.
* **No Em-Dashes:** Never use em-dashes in Markdown, UI copy, or responses.
* **Direct Agent Rules:** Format agent rules strictly as **Trigger -> Action -> Timing**.
